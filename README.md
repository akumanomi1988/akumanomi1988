## About me

I'm **AkumaDev**, a full-stack software developer focused on turning complex requirements into **robust, maintainable products**. I work across the entire software lifecycle: domain modelling, data architecture, APIs, desktop and web interfaces, integrations, automation, testing, and deployment.

My background spans the **.NET ecosystem, enterprise software and SQL-backed systems**, while my current work extends into **React / TypeScript, cloud platforms, AI-assisted products and hybrid desktop applications**. I'm particularly interested in connecting mature business software with modern interfaces and services **without sacrificing reliability or introducing unnecessary complexity**.

I build both **professional software and independent products**. The technical problem interests me; so does the product question behind it: *Can this be maintained, operated, scaled, and delivered sustainably?*

## Engineering principles

My preferred architecture is **as simple as possible, but no simpler than the operational requirements allow**.

| Principle | What it means in practice |
|:--|:--|
| **Reliability before novelty** | Protect data integrity, recovery paths and real user flows before chasing new abstractions. |
| **Modular by design** | High cohesion, explicit boundaries, low coupling and reusable domain logic. |
| **Scale where it matters** | Measure bottlenecks; plan for growth without paying the complexity tax too early. |
| **Make the database an ally** | Model constraints, concurrency, access policies, migrations and query costs deliberately. |
| **Security is architecture** | Validate identities, enforce authorization at boundaries and keep secrets out of code. |
| **Test meaningful behavior** | Prefer regression, integration and end-to-end evidence over cosmetic coverage numbers. |
| **Optimize for ownership** | Deployment, diagnostics, operational cost and future maintainers are part of the design. |

### A pattern I keep coming back to

A native desktop shell can coexist with a modern React experience without turning everything into a web service. Equally, a product can begin as a **modular monolith** and evolve when the load, team or integration boundaries actually justify separation.

```text
                  Product experience
            ┌────────────┴────────────┐
       Native desktop             Web interface
      WinForms / WebView2          React / Next.js
            └────────────┬────────────┘
                Application contracts
                         │
              Domain & use-case logic
                         │
         ┌───────────────┼───────────────┐
       Data           Integrations     AI services
     SQL / PG        APIs / events     RAG / LLMs
```

The drawing is conceptual, not a claim that every repository uses the same architecture.
